Yesterday I opened the Databricks run history and saw a picket fence.

Dozens of runs in a few hours. Every scrape was triggering the pipeline twice — once from the file upload (file_arrival), once from the API call. Both had comments saying "primary trigger" in different config files. Both were right. Both were wrong together.

It got worse: each run wrote a uniquely-timestamped file. So every debug re-run created a new file, each one firing the pipeline again. A few hours of debugging × 2 triggers per upload = the pattern you see in the screenshot.

The fix was mass:
→ One fixed filename that overwrites itself (no more pile-up)
→ One trigger mechanism (API-only, file_arrival removed entirely)
→ One upload → one run. Period.
